# T003：数据库与 ORM 持久化基础

## 1. 任务目标

在现有 job_agent 工程和 T002 领域模型基础上，建立独立、可测试、可迁移的数据库持久化基础。

本任务负责：

- 数据库连接与会话管理
- SQLAlchemy ORM 基础设施
- ORM 持久化模型
- 领域模型与 ORM 模型之间的转换
- 数据库初始化和迁移
- 数据库基础测试

本任务不实现 Repository CRUD、业务服务、岗位匹配、LLM Agent、LangGraph、Playwright 或 Streamlit。

## 2. 前置条件

开始 T003 前应满足：

- T001 工程骨架已经完成
- T002 领域模型与枚举已经完成
- T002 已通过完整测试
- T002 已形成稳定 Git 检查点
- 当前使用 Python 3.11+
- 当前开发分支为 feat/T003-persistence-foundation

## 4. 数据库要求

默认开发数据库：

sqlite:///./data/job_agent.db

要求：

- 数据库地址从现有配置系统读取
- 不在业务代码中重复硬编码数据库地址
- 测试使用临时数据库
- 测试不得读写真实 data/job_agent.db
- 数据库文件不得提交到 Git
- SQLite 必须启用外键约束

## 5. ORM 要求

使用 SQLAlchemy 的现代类型化声明方式。

要求：

- 使用独立 Declarative Base
- ORM 模型与 Pydantic 领域模型分离
- 使用明确的表名、主键、外键和约束
- 枚举以稳定字符串值持久化
- 不使用隐式全局 Session
- 模块导入时不连接数据库
- 模块导入时不创建数据库文件
- 模块导入时不自动创建数据表
- job_agent/domain 不得导入 SQLAlchemy、Alembic 或数据库 Session

可以根据现有架构调整文件名称，但必须保持职责清晰：

- 正常事务提交
- 异常事务回滚

- 数据库初始化入口

## 7. ORM 持久化模型

根据 T002 领域模型和数据模型文档建立 ORM 模型。

要求：

- 领域模型继续作为业务数据契约
- ORM 模型只负责持久化
- 明确主键和外键关系
- 明确必要的唯一约束和索引
- 明确级联删除策略
- 不擅自修改已有枚举值
- 不擅自修改 T002 的公开导入路径

如果 T002 模型缺少数据库所需的内部字段，应优先将字段保留在 ORM 层。

只有字段确实属于领域契约时，才允许修改领域模型，并且必须说明原因、兼容性影响并增加测试。

## 8. datetime 与枚举

T002 领域模型要求 datetime 携带时区。

持久化必须保证：

- 写入前验证 datetime 含时区
- 使用统一时区策略
- 从数据库读取后仍能生成合法领域模型
- 不静默丢失时区语义
- 枚举写入和读取后保持相同字符串值

## 9. 嵌套与可变数据

对于列表、字典和嵌套对象，应根据数据用途选择关系表、子表或 JSON 字段。

要求：

- 需要独立查询、排序或关联的数据优先使用关系表
- 只作为快照且无需独立查询的数据可以使用 JSON
- 不得把所有领域对象直接存入一个大 JSON 字段
- 最终报告必须说明选择理由

## 10. 映射层

实现领域模型和 ORM 模型之间的显式转换。

例如：

- candidate_to_orm
- candidate_to_domain
- job_to_orm
- job_to_domain

要求：

- 不使用不受控制的 model_dump 全量灌入 ORM
- Pydantic 模型不依赖 SQLAlchemy
- 映射逻辑可以独立测试
- 枚举、datetime 和嵌套数据能够正确往返
- 转换失败时提供明确异常

## 11. 数据库迁移

建立项目数据库迁移机制。

要求：

- 迁移配置读取项目 DATABASE_URL
- 不在迁移文件中写真实密钥
- 不在迁移文件中写本机绝对路径
- 提供初始迁移
- upgrade 可以创建本任务定义的表
- downgrade 可以撤销对应结构
- 迁移文件必须提交到 Git
- SQLite 数据库文件不得提交

如果原始开发文档明确把迁移放到后续任务，本任务只建立兼容迁移的 metadata 和数据库初始化方式，并在最终报告中说明。

## 14. 测试要求

测试至少覆盖：

### Engine 和配置

- 可以从测试数据库 URL 创建 Engine
- 模块导入不会创建真实数据库
- 无效配置产生明确错误
- 测试不会访问真实数据库

### Session 生命周期

- 正常事务能够提交
- 异常时能够回滚
- 使用结束后 Session 被关闭
- 测试之间不存在状态污染

### ORM 结构

- 数据表可以创建
- 主键、外键和唯一约束有效
- SQLite 外键约束启用
- 删除和级联行为符合设计

### 映射

- 领域模型可以转换为 ORM 模型
- ORM 模型可以恢复为合法领域模型
- 枚举往返一致
- datetime 时区语义往返一致
- 嵌套数据往返一致

### 迁移

如果引入迁移：

- 空数据库可以升级到最新版本
- 升级后存在预期表
- downgrade 可以执行
- 迁移不依赖本机绝对路径
