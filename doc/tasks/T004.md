# T004：Repository 与事务层

## 1. 任务目标

基于 T003 的 SQLAlchemy 持久化基础，实现面向领域模型的 Repository 接口、SQLAlchemy Repository 实现、事务边界、CRUD、upsert 和分页。

Repository 对外使用领域模型，不向业务层暴露 ORM 实体。

## 4. 实现范围

实现以下 Repository：

- CandidateRepository
- ResumeEvidenceRepository
- JobRepository
- MatchRepository
- ResumeVersionRepository
- ApplicationRepository

ApplicationRepository 应在 Application 聚合边界内处理：

- ApplicationAnswer
- ApplicationEvent

如果现有架构明确要求 Answer 和 Event 使用独立 Repository，可以遵循架构文档，但必须说明设计理由。

## 5. 分层要求

Repository 接口与 SQLAlchemy 实现必须分离。

建议目录：

    job_agent/
      application/
        ports/
          repositories.py
      infrastructure/
        database/
          repositories/
            __init__.py
            candidate.py
            evidence.py
            job.py
            match.py
            resume.py
            application.py
            exceptions.py

可以根据现有架构调整，但必须满足：

- Repository 接口不得依赖 SQLAlchemy
- 业务层不得导入 ORM 实体
- Repository 对外返回 Pydantic 领域模型
- ORM 与领域模型通过 T003 Mapper 转换
- 不得直接把 SQLAlchemy Query 暴露给调用方

## 6. CRUD

根据实体特征实现：

- add
- get_by_id
- list
- update
- delete

查询不到数据时的行为必须统一。

可以统一返回 None，也可以抛出项目级异常，但不得让不同 Repository 使用互相矛盾的规则。

update 必须明确：

- 哪些字段允许修改
- 实体不存在时如何处理
- 不得静默创建不存在的实体
- 不得覆盖不可变业务字段

delete 必须明确：

- 删除不存在记录时的行为
- 级联删除行为
- 是否返回删除结果

## 7. Upsert

只对具有明确业务唯一键的实体实现 upsert：

- Job：fingerprint
- Resume：candidate_id + content_hash
- Match：candidate_id + job_id
- Application：candidate_id + job_id

要求：

- 相同业务键重复写入不会创建重复记录
- 明确哪些字段允许更新
- 不得静默覆盖不可变字段
- upsert 后返回最新领域模型
- SQLite 下行为必须可测试
- 唯一约束冲突不得导致 Session 留在不可用状态

不得为所有实体机械增加 upsert。

## 8. 分页

列表查询必须支持分页和稳定排序。

要求：

- limit 必须大于 0
- limit 必须有合理上限
- offset 不得为负数
- 默认排序必须确定
- 相同数据重复查询的顺序一致
- 返回当前页数据和总数量
- 空结果行为明确
- 分页参数错误必须产生明确异常

可以定义独立的分页结果类型，但不得依赖 ORM 类型。

## 9. 事务边界

Repository 不得自行 commit。

Repository 可以：

- add
- delete
- flush
- refresh

事务提交与回滚由外层事务上下文控制。

要求：

- 多个 Repository 可以使用同一个 Session
- 多个 Repository 可以参与同一个事务
- 任一步失败时整个事务回滚
- 回滚后不得留下部分写入
- Repository 方法不得隐藏提交行为
- Session 生命周期继续使用 T003 基础设施管理

如果实现 Unit of Work，只实现事务协调，不加入业务流程。

## 10. 异常处理

建立统一、最小化的持久化异常，例如：

- RepositoryError
- EntityNotFoundError
- DuplicateEntityError
- InvalidPaginationError

要求：

- 不向业务层直接泄漏 SQLAlchemy 异常
- 使用异常链保留原始异常
- 不捕获并吞掉异常
- 唯一约束冲突转换为明确异常
- 参数错误和数据库错误必须区分
- 异常后事务能够正确回滚

## 11. Migration 约束

原则上 T004 不修改数据库 Schema。

如确实缺少必要索引或约束：

1. 不得修改 migrations/versions/0001_initial_persistence.py
2. 必须新增 0002 migration
3. upgrade 和 downgrade 都必须验证
4. 必须说明 T003 Schema 无法满足需求的原因
5. migration 必须使用显式不可变 Alembic DDL

## 12. 测试要求

至少覆盖：

### Repository 基础行为

- 新增实体
- 按 ID 查询
- 更新实体
- 删除实体
- 查询不存在的实体
- 删除不存在的实体
- 返回领域模型而不是 ORM 模型

### 唯一约束与 Upsert

- Job fingerprint upsert
- Resume 业务键 upsert
- Match 业务键 upsert
- Application 业务键 upsert
- 重复 upsert 不产生重复记录
- 不可变字段不被静默覆盖
- 唯一约束冲突转换为项目异常

### 分页

- 正常分页
- 空结果
- limit 边界
- offset 边界
- 稳定排序
- 总数正确
- 不同页不存在意外重复数据

### 事务

- 单个 Repository 事务提交
- 多个 Repository 共享事务
- 中途失败后整体回滚
- 回滚后 Session 状态可以继续管理
- Repository 不自行 commit
- flush 后外层 rollback 不保留数据

### 测试隔离

- 测试使用 pytest 临时数据库
- 不读写 data/job_agent.db
- 测试之间不存在状态污染
- 不调用真实外部服务
