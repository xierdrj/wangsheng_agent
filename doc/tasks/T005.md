# T005：Profile Service

## 1. 任务目标

基于 T002 领域模型和 T004 Repository 层，实现 Profile Service。

本任务负责：

- 创建 Candidate Profile
- 查询 Candidate Profile
- 编辑 Candidate Profile
- 导入结构化候选人资料
- 新增和管理 ResumeEvidence
- 显式验证 Evidence
- 提供只返回 VERIFIED Evidence 的正式查询
- 在资料修改时正确更新时间
- 保证跨 Repository 操作的事务一致性

本任务不实现 Job/Application Service、LLM、LangGraph、简历解析、岗位搜索、匹配算法、Playwright 或 Streamlit。

## 4. 分层要求

Profile Service 属于 application service 层。

建议结构：

    job_agent/
      application/
        contracts/
          profile.py
        services/
          __init__.py
          profile.py
        ports/
          repositories.py
          unit_of_work.py

如果需要数据库事务适配，可在 infrastructure 层增加 SQLAlchemy Unit of Work 实现。

要求：

- application service 不导入 SQLAlchemy
- application service 不导入 ORM 实体
- application service 依赖 Repository 或 Unit of Work 抽象
- service 对外返回 Pydantic 领域对象或应用层 DTO
- 不重复实现 T003 Mapper
- 不直接操作数据库表

## 5. Profile 创建

创建 Profile 时：

- 使用现有 CandidateProfile 进行校验
- 禁止额外未知字段
- ID 重复时产生明确冲突错误
- created_at 和 updated_at 必须带时区
- created_at 和 updated_at 初始值应一致或符合现有数据契约
- 不允许调用方伪造不合理的更新时间
- 创建结果返回 CandidateProfile
- 不返回 CandidateORM

如果现有 CandidateProfile 已要求调用方提供时间字段，应保持兼容，并在 Service 层规范化时间语义。

## 6. Profile 查询

至少提供：

- 按 Candidate ID 查询 Profile
- 查询不到时返回 None 或项目统一的 NotFound 行为
- 查询结果为 CandidateProfile
- 不返回 ORM 实体

查询 Profile 时不得隐式返回未验证 Evidence。

Profile 与 Evidence 应通过明确方法分别查询，避免调用方误把未验证证据用于正式材料。

## 7. Profile 编辑

编辑 Profile 时：

- Candidate 不存在时产生 EntityNotFoundError
- 保留 Candidate ID
- 保留 created_at
- 每次成功修改必须更新 updated_at
- updated_at 使用 timezone-aware UTC 时间
- 更新失败时不得留下部分修改
- 不允许通过普通编辑修改其他 Candidate 的数据
- 不得通过编辑操作静默创建 Profile

时间获取必须可测试。可以使用可注入 Clock 或 now 函数，避免测试依赖真实等待时间。

## 8. 结构化资料导入

本任务中的“结构化资料导入”只处理已经结构化的数据。

允许输入：

- CandidateProfile 兼容数据
- Education、Experience、JobPreference 等现有嵌套结构
- ResumeEvidence 兼容数据

不实现：

- PDF、Word 或图片解析
- OCR
- LLM 信息抽取
- 自然语言简历解析
- 外部文件下载

要求：

- 先完成整个输入的 Pydantic 校验，再写入数据库
- 未知字段被拒绝
- 非法 URL、时间、枚举和范围值被拒绝
- Candidate 与 Evidence 的批量写入必须处于同一事务
- 任意一项失败时整体回滚
- 不产生半完成 Profile
- 导入的 Evidence 默认保持 UNVERIFIED
- 导入操作不得自动将 Evidence 标记为 VERIFIED
- 重复数据行为必须明确，不得静默制造重复 Evidence
- 导入成功后返回领域对象或明确的导入结果 DTO

## 9. Evidence 新增

新增 Evidence 时：

- 必须关联已存在的 Candidate
- 输入经过 ResumeEvidence 校验
- 默认 verification 为 UNVERIFIED
- 不能通过普通新增接口绕过验证流程直接写入 VERIFIED
- 如确需导入已有 VERIFIED 数据，必须使用明确且受控的专用路径，并记录设计理由
- Candidate 不存在时整个操作失败
- 不返回 Evidence ORM 实体

## 10. Evidence 验证

必须提供显式验证操作。

要求：

- 只有现有 Evidence 可以被验证
- Evidence 不存在时产生 EntityNotFoundError
- 验证后 verification 变为 VERIFIED
- 重复验证应具有明确且可测试的幂等行为
- 不得修改 Evidence 所属 Candidate
- 不得静默修改 Evidence 原始内容
- 验证操作发生在明确事务中
- 不得根据 LLM 输出自动验证 Evidence

现有枚举只有 UNVERIFIED 和 VERIFIED，不得自行增加第三种状态。

## 11. Evidence 查询边界

至少区分两类查询：

### 审核查询

用于查看和验证 Evidence，可以返回：

- UNVERIFIED
- VERIFIED

### 正式查询

用于后续简历生成、材料生成和正式业务，只能返回：

- VERIFIED

要求：

- 正式查询必须在 Service 或 Repository 查询条件中强制过滤
- 调用方不能通过参数关闭 VERIFIED 限制
- 无 VERIFIED Evidence 时返回空集合
- 不得用未验证 Evidence 填充结果
- 分页时过滤必须在分页之前完成
- total 必须表示 VERIFIED 结果总数
- 不允许先分页再在内存中过滤

本任务不实现 T106 Evidence Retriever 的语义检索、排序或召回功能。

## 12. 事务边界

Profile Service 不应直接调用 Session.commit。

可以通过 Repository 和事务抽象完成操作。

要求：

- 创建 Profile 与批量 Evidence 导入可处于同一事务
- 多个 Repository 可以共享同一事务
- 任一步失败时整体回滚
- 回滚后不得留下 Candidate 或 Evidence 的部分写入
- application service 不依赖 SQLAlchemy Session 类型
- 基础设施层负责实际 Session 生命周期

如果增加 Unit of Work：

- application 层只定义 Protocol
- SQLAlchemy 实现位于 infrastructure 层
- Unit of Work 只协调事务，不包含业务规则
- 不得与 T004 session_scope 形成冲突或重复提交

## 13. 错误处理

复用 T004 已有项目级异常。

至少正确处理：

- Candidate 不存在
- Evidence 不存在
- Candidate ID 冲突
- 非法结构化输入
- Evidence 关联错误
- 数据库唯一约束冲突
- 事务失败

要求：

- 不向调用方直接泄漏 SQLAlchemy 异常
- 不吞掉原始异常
- 使用异常链保留根因
- 校验错误与数据库错误应可区分

## 14. Schema 与 Migration

原则上 T005 不修改数据库 Schema。

如果现有表缺少 updated_at 或完成验收必需的字段：

1. 不得修改 0001_initial_persistence.py
2. 必须新增独立 migration
3. 必须验证 upgrade 和 downgrade
4. 必须说明新增字段的业务必要性
5. 不得为了方便测试随意修改 Schema

至少覆盖：

### Profile

- 创建 Profile
- 查询 Profile
- 查询不存在的 Profile
- 编辑 Profile
- 编辑不存在的 Profile
- 编辑后 updated_at 发生变化
- 编辑后 created_at 保持不变
- datetime 保持 timezone-aware
- Service 不返回 ORM 实体

### 结构化导入

- 导入合法结构化资料
- 未知字段被拒绝
- 嵌套字段校验失败
- 非法数据整体回滚
- Candidate 和多个 Evidence 原子写入
- 导入 Evidence 默认 UNVERIFIED
- 导入不会自动验证 Evidence

### Evidence

- 新增 Evidence
- 新增时默认 UNVERIFIED

- 重复验证的幂等行为
- 验证不存在的 Evidence
- Evidence 与 Candidate 关联正确
- 审核查询可查看全部状态

- 没有 VERIFIED Evidence 时返回空集合
- 正式查询分页 total 正确
- 过滤发生在数据库分页之前

### 事务与架构

- 跨 Repository 操作共享事务
- 中途失败后整体回滚
- application service 不导入 SQLAlchemy
- service 不调用 commit
- 不返回 ORM 实体
- 测试只使用临时数据库
- 不读写 data/job_agent.db
