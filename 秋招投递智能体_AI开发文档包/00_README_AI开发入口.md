# 秋招投递智能体：AI 开发入口

## 1. 这套文档如何使用

本目录是编程智能体的权威上下文。原始总方案用于背景参考；真正编码时，以本目录中编号文档为准。

编程智能体每次开始任务时：

1. 必读本文件；
2. 读取 `01_产品需求与范围.md`；
3. 读取 `11_AI编程执行规范.md`；
4. 根据任务类型，读取下表指定的专题文档；
5. 读取 `10_开发路线与任务清单.md` 中当前任务的验收标准；
6. 检查仓库现状和已有测试后再修改代码。

不要在每个任务中无差别读取全部文档。只有跨模块设计或发现契约冲突时，才扩大读取范围。

## 4. 文档优先级

出现冲突时，按以下顺序处理：

1. 用户在当前会话中的明确要求；
2. 已通过测试体现的现有业务行为；
3. `01_产品需求与范围.md` 中的安全和业务边界；
4. `03_领域模型与数据契约.md` 中的契约；
5. 其他专题设计文档；
6. 原始总方案。

如果现有代码、测试和文档三者冲突，不要自行猜测。记录冲突，给出最小可选方案并请求用户确认。

## 5. 当前推荐实现范围

当前优先实现 V0.1：

```text
工程骨架
→ 配置与数据库
→ Candidate Profile
→ Resume Evidence Bank
→ 岗位手动录入
→ ApplicationRecord
→ 基础 Streamlit 页面
```

在 V0.1 验收前，不实现真实招聘网站提交、验证码处理和邮件监听。

## 6. 全局硬约束

- 不得编造候选人经历、技能、数字或成果；
- 所有生成内容必须可追溯到 `source_evidence_ids`；
- 最终提交网申必须经过人工确认；
- 不绕过验证码、登录控制和网站安全机制；
- 密码、Cookie、Token、身份证号不得写入日志或 Git；
- 业务数据库与 LangGraph Checkpoint 分工明确；
- 外部副作用必须可重试、可审计，并尽量幂等；
- 默认以 `dry_run` 方式开发浏览器自动化；
- 每个功能必须有验收测试。
