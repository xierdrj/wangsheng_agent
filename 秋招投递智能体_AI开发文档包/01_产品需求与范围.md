# 产品需求与范围

## 1. 产品定位

本项目是一个本地运行、由用户保持最终控制权的秋招工作流系统。它帮助用户发现岗位、判断匹配度、生成有事实依据的申请材料、辅助填写网申并追踪进度。

它不是无人监督的“自动海投机器人”。核心目标是提高信息整理和重复填写效率，同时保证真实性、可追溯性和投递安全。

## 2. 目标用户

第一阶段只支持单用户、本地使用。系统可以针对技术岗或非技术岗配置不同求职意向，但所有用户数据均通过统一领域模型管理。

## 3. 核心用户故事

### US-01：建立个人求职档案

用户可以导入简历或手动填写个人资料，校对系统抽取的教育、实习、项目、技能和证据条目。

验收：系统保存结构化 Profile；任何生成内容都可以关联到已验证证据。

### US-02：发现和筛选岗位

用户配置求职方向、地点、毕业年份等条件，系统搜索或导入岗位，完成去重、硬过滤和语义匹配。

验收：每个推荐岗位包含分数、优势、缺口和证据来源，而不是只有一个不可解释分数。

### US-03：针对 JD 定制材料

用户选择某个岗位，系统根据真实证据调整简历内容顺序和表达，并生成网申问题草稿。

验收：系统不得新增无来源事实；缺失能力明确显示为 gap。

### US-04：辅助填写网申

系统打开用户选定的申请页面，识别字段、映射个人资料、上传选定简历，在最终提交前暂停。

验收：用户可以查看和修改所有字段；验证码由用户完成；提交必须人工批准。

### US-05：记录和追踪进度

系统保存投递时的 JD、简历、答案、截图、状态和事件，并允许用户更新后续笔试、面试和 Offer 状态。

验收：用户能够回答“给这家公司投了哪个版本、填了什么、何时状态发生变化”。

## 4. 功能范围

### 4.1 V0.1 必须实现

- 工程骨架和统一配置；
- SQLite 数据库与迁移；
- Candidate Profile 的创建、查看、编辑；
- Resume Evidence Bank 的创建、校对、查询；
- 求职意向配置；
- JobPosting 手动录入；
- ApplicationRecord 创建与状态更新；
- 基础 Streamlit 页面；
- 单元测试和基础集成测试。

### 4.2 后续实现

- 岗位自动搜索与 JD 解析；
- 去重、硬过滤和语义匹配；
- 简历版本与网申答案生成；
- LangGraph 中断、审批和恢复；
- 单个 ATS 的 Playwright Adapter；
- 招聘邮件解析；
- 多平台扩展和定时任务。

## 5. 非目标

以下不属于第一阶段目标：

- 同时支持所有招聘网站；
- 自动绕过滑块、短信或图形验证码；
- 未经用户确认自动提交申请；
- 为匹配 JD 虚构经历；
- 第一版即支持多租户和云端部署；
- 第一版即引入向量数据库、复杂消息队列或微服务；
- 自动代表用户回答法律声明、背景调查或价值判断类问题。

## 6. 关键业务规则

### 6.1 真实性

- 候选人事实以已验证 Profile 和 Evidence 为准；
- LLM 输出必须包含证据 ID；
- 无证据的要求不得转换为候选人能力；
- 用户手工修改生成内容后，仍要执行事实一致性检查。

### 6.2 投递控制

- 只有进入待投池的岗位才能启动 Application Graph；
- 同一候选人和同一岗位默认只能有一个有效投递；
- 最终提交前强制 `interrupt()`；
- 所有浏览器任务默认 `dry_run=True`；
- 撤回、覆盖和删除操作需要单独确认。

### 6.3 状态管理

合法主状态：

```text
DISCOVERED → SHORTLISTED → PREPARING → READY_TO_APPLY
→ SUBMITTED → ONLINE_ASSESSMENT → INTERVIEW → OFFER
```

终止状态：`REJECTED`、`WITHDRAWN`、`CLOSED`。

状态变化必须形成 `ApplicationEvent`，不能只覆盖当前状态。

### 6.4 隐私

- 对外模型调用只发送当前任务所需字段；
- 敏感字段与普通 Profile 分开管理；
- 日志必须脱敏；
- 认证状态不进入 Git 和数据库正文；
- 页面默认不完整展示身份证号、手机号等敏感信息。

## 7. 质量属性

| 属性 | 要求 |
|---|---|
| 可解释性 | 匹配和生成结果能够追溯到证据 |
| 可恢复性 | 中断或异常后可以从 Checkpoint 恢复 |
| 可审计性 | 投递有事件、快照、材料版本和审批记录 |
| 可维护性 | ATS 变化只影响对应 Adapter |
| 安全性 | 高风险操作需人工批准，敏感数据最小暴露 |
| 可测试性 | 外部网站和 LLM 可通过接口替身测试 |
| 幂等性 | 重试不会产生重复投递或重复业务记录 |

## 8. 成功指标

- 推荐岗位有效率；
- 去重准确率；
- 匹配结论证据覆盖率；
- 生成内容事实一致率；
- 表单字段识别和映射准确率；
- 中断后工作流恢复率；
- 投递快照完整率；
- 单次申请节省时间。
