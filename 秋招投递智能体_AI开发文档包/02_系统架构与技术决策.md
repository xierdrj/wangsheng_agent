# 系统架构与技术决策

## 1. 架构目标

系统采用“模块化单体”架构。第一阶段保持一个 Python 项目和一个数据库，通过清晰接口隔离领域、工作流、模型、浏览器、持久化和 UI。达到明确扩展需求后再考虑拆分服务。

## 2. 分层架构

```text
UI / API
  ↓
Application Services
  ↓
LangGraph Orchestration
  ↓
Domain Rules / Agent Ports / Browser Ports
  ↓
Repositories / LLM Providers / Playwright Adapters
```

### 2.1 Presentation

- Streamlit 页面；
- 可选 FastAPI；
- 只负责输入校验、调用 Service 和展示结果；
- 不直接写数据库，不直接操作 Playwright。

### 2.2 Application Services

- 组织单个用例；
- 管理数据库事务；
- 调用 Graph 或领域服务；
- 将领域对象转换为页面/API DTO。

### 2.3 Workflow

- LangGraph 管理节点顺序、条件路由、重试、中断与恢复；
- State 只保存完成工作流所需的引用和中间结果；
- 大对象和正式业务数据写入业务数据库或文件存储。

### 2.4 Domain

- Pydantic Schema、枚举、纯规则和状态转换；
- 不依赖 Streamlit、Playwright 或具体 LLM SDK；
- 确定性规则优先写成普通 Python 函数。

### 2.5 Infrastructure

- SQLAlchemy Repository；
- LangGraph Checkpointer；
- LLM Provider；
- Playwright Browser Manager 和 ATS Adapter；
- 文件与快照存储。

## 3. 依赖方向

允许：

```text
app → services → domain
graphs → domain + ports
infrastructure → domain interfaces
```

禁止：

- `domain` 导入 Streamlit；
- `domain` 导入 Playwright；
- Page 直接执行 SQLAlchemy 查询；
- Graph Node 直接拼接平台专用 CSS Selector；
- Prompt 文件中定义业务状态转换规则；
- Repository 返回未约束的任意字典。

## 6. 关键技术决策

### ADR-001：使用模块化单体

原因：当前是单用户本地项目，模块化单体更易开发、调试和测试。微服务会引入不必要的部署和一致性成本。

### ADR-002：Schema 是模块边界

网页、LLM 输出、API 和数据库都必须先转换为受约束的 Schema。不得让任意 JSON 在多层之间传播。

### ADR-003：业务库与 Checkpoint 分离

业务数据库保存岗位、材料和投递事实；Checkpoint 保存 Graph 的运行位置和可恢复状态。两者不能互相替代。

### ADR-004：LLM 通过 Port 调用

领域和 Graph 依赖 `LLMClient` 接口，不绑定具体供应商。测试使用 Fake Client 返回固定结构化结果。

### ADR-005：Playwright 平台差异由 Adapter 隔离

Graph 只调用统一 `ApplicationAdapter` 接口。Selector、页面步骤和平台异常留在具体 Adapter 内。

### ADR-006：第一版不强制向量数据库

个人证据规模较小时，使用结构化标签、关键词和可替换的语义检索接口即可。检索效果或规模证明有需要时再接入 FAISS/Chroma。

## 7. 配置规范

配置来源优先级：环境变量 > `.env` > 安全默认值。

建议配置域：

```text
APP_ENV
DATABASE_URL
LLM_PROVIDER
LLM_MODEL
LLM_API_KEY
DATA_DIR
SNAPSHOT_DIR
PLAYWRIGHT_AUTH_DIR
BROWSER_HEADLESS
BROWSER_DRY_RUN
LOG_LEVEL
MAX_DAILY_SUBMISSIONS
```

`.env.example` 只保存键名和非敏感示例；真实密钥不得写入仓库。

## 8. 错误分类

统一错误类别：

- `ValidationError`：输入或 Schema 不合法；
- `DomainRuleError`：违反状态或业务规则；
- `ExternalServiceError`：LLM、搜索或邮件服务失败；
- `BrowserAutomationError`：页面识别、定位、填写失败；
- `HumanActionRequired`：登录、验证码、审批；
- `PersistenceError`：数据库、Checkpoint、文件存储失败；
- `ConfigurationError`：配置缺失或冲突。

错误向上层返回机器可判断的 `code` 和用户可理解的 `message`，原始异常写入脱敏日志。
