# 领域模型与数据契约

## 1. 通用规范

- ID 使用 UUID 字符串；
- 时间使用带时区的 ISO 8601；
- URL 使用 Pydantic URL 类型或显式校验；
- 枚举值在代码和数据库中统一使用大写英文；
- 可选字段明确写为 `T | None`；
- 所有 LLM 输出必须通过 Pydantic 校验；
- 领域对象不包含 ORM Session、Page、Browser 或 LLM SDK 对象。

## 3. Candidate Profile

```python
from datetime import date, datetime
from pydantic import BaseModel, ConfigDict, EmailStr, Field


class BasicInfo(BaseModel):
    full_name: str
    email: EmailStr
    phone: str
    city: str | None = None
    sensitive_profile_id: str | None = None


class Education(BaseModel):
    id: str
    school: str
    degree: str
    major: str
    start_date: date | None = None
    end_date: date | None = None
    gpa: str | None = None


class Experience(BaseModel):
    id: str
    organization: str
    title: str
    start_date: date | None = None
    end_date: date | None = None
    description: str


class JobPreference(BaseModel):
    roles: list[str] = Field(min_length=1)
    locations: list[str] = []
    industries: list[str] = []
    graduation_year: int | None = None
    salary_expectation: str | None = None
    excluded_companies: list[str] = []
    accepts_travel: bool | None = None
    accepts_relocation: bool | None = None


class CandidateProfile(BaseModel):
    model_config = ConfigDict(extra="forbid")

    id: str
    basic_info: BasicInfo
    education: list[Education] = []
    internships: list[Experience] = []
    projects: list[Experience] = []
    skills: list[str] = []
    awards: list[str] = []
    preferences: JobPreference
    created_at: datetime
    updated_at: datetime
```

敏感信息单独存储，Profile 通过 `sensitive_profile_id` 引用。第一版若暂未实现加密存储，也必须避免把敏感对象传给 LLM 和日志。

## 4. Resume Evidence

```python
class ResumeEvidence(BaseModel):
    id: str
    candidate_id: str
    experience_id: str | None = None
    category: str
    content: str
    skills: list[str] = []
    metrics: list[str] = []
    source_resume_id: str | None = None
    verification: EvidenceVerification = EvidenceVerification.UNVERIFIED
    created_at: datetime
    updated_at: datetime
```

约束：

- `content` 必须是一条可独立引用的事实；
- 包含数字时，数字应在原始简历或用户确认记录中存在；
- `REJECTED` 证据不得用于生成；
- 默认只有 `VERIFIED` 证据可进入最终材料。

## 6. MatchResult

class MatchDimension(BaseModel):
    name: str
    score: float = Field(ge=0, le=100)
    weight: float = Field(ge=0, le=1)

class MatchResult(BaseModel):
    id: str

    hard_filter_passed: bool

## 8. 表单字段

```python
class FormField(BaseModel):
    id: str
    label: str | None = None
    field_type: str
    required: bool = False
    options: list[str] = []
    locator_hint: dict = {}
    mapped_source: str | None = None
    proposed_value: str | None = None
    confidence: float = Field(default=0, ge=0, le=1)
    needs_review: bool = False
    sensitive: bool = False
```

映射规则：

- `confidence >= 0.90`：允许自动填充；
- `0.60 <= confidence < 0.90`：自动填充但强制复核；
- `< 0.60`：不自动填充；
- `sensitive=True`：无论置信度如何都强制复核。

## 10. 状态转换

状态转换由普通 Python 规则校验，不由 LLM 决定。

允许从当前状态向后推进，也允许进入终止状态。`REJECTED`、`WITHDRAWN`、`CLOSED` 默认不可自动恢复；若用户要求恢复，必须创建人工事件说明原因。

## 11. LangGraph State 原则

Graph State 存储：

- 当前业务 ID；
- 运行阶段；
- 已校验的小型结构化中间结果；
- 待人工操作内容；
- 错误代码。

Graph State 不存储：

- 完整 PDF 字节；
- Browser/Page 对象；
- ORM Session；
- 密码和 Cookie；
- 超大原始网页内容；
- 可从业务数据库按 ID 重新读取的全部历史对象。
