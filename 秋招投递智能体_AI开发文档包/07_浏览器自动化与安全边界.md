# 浏览器自动化与安全边界

## 1. 目标

浏览器层负责在用户选择的招聘页面上识别表单、填写资料、上传简历、校验错误并在获得明确批准后提交。它不负责岗位匹配和内容真实性判断。

## 2. 架构

```text
BrowserManager
├── SessionStore
├── AdapterFactory
└── ApplicationAdapter
    ├── PageAnalyzer
    ├── FormExtractor
    ├── FieldMapper
    ├── FormFiller
    ├── Validator
    └── Submitter
```

## 3. Adapter 接口

```python
from typing import Protocol


class ApplicationAdapter(Protocol):
    async def detect(self) -> bool: ...
    async def ensure_authenticated(self) -> None: ...
    async def parse_form(self) -> list[dict]: ...
    async def fill_form(self, fields: list[dict]) -> None: ...
    async def upload_resume(self, file_path: str) -> None: ...
    async def validate(self) -> list[dict]: ...
    async def capture_snapshot(self, stage: str) -> str: ...
    async def submit(self, approval_token: str) -> None: ...
    async def verify_submission(self) -> dict: ...
```

AdapterFactory 根据域名、页面特征和已注册规则选择 Adapter。无法可靠识别时使用 GenericAdapter 的只读分析模式，不自动提交。

## 4. 定位器策略

优先级：

1. `get_by_role`；
2. `get_by_label`；
3. `get_by_placeholder`；
4. 稳定的 `data-*` 属性；
5. 平台专用 CSS；
6. XPath 仅作为最后手段。

平台专用 Selector 只能存在于对应 Adapter 或 Page Object 中。

禁止：

- 使用长链式易碎 XPath 作为主策略；
- 在 Graph Node 中散落 Selector；
- 遇到多个匹配元素时默认点击第一个；
- 未验证当前步骤就执行下一步。

## 5. 表单分析流程

```text
读取页面状态
→ 检测登录/验证码/弹窗
→ 提取可见字段
→ 识别字段类型与选项
→ 映射个人资料或生成答案
→ 按置信度分类
→ 填写非敏感高置信字段
→ 校验并生成预览
```

每个字段保存：label、type、required、options、locator_hint、mapped_source、value、confidence、sensitive、needs_review。

## 6. 敏感字段

以下字段默认强制人工复核：

- 身份证、护照、出生日期；
- 薪资和期望薪资；
- 是否服从调剂；
- 是否接受外派、轮岗、夜班；
- 家庭成员；
- 背景调查、竞业限制；
- 法律声明和诚信承诺；
- 政治、健康、残障等敏感信息。

LLM 不得替用户做价值判断。

## 7. 登录态

- 首次登录由用户操作；
- 可使用 Playwright `storage_state` 复用会话；
- 状态文件保存在本地受控目录；
- `auth/` 写入 `.gitignore`；
- 日志不得输出 Cookie、Token、local storage；
- 登录失效时触发 `HumanActionRequired`，不自动尝试密码。

## 8. 验证码

遇到短信、图形、滑块或人机验证：

1. 截图并记录当前步骤；
2. 触发 LangGraph `interrupt()`；
3. 用户在同一浏览器上下文中完成验证；
4. 恢复后重新检查页面状态；
5. 不调用验证码破解或规避服务。

## 9. Dry Run 与正式提交

默认：

```text
BROWSER_DRY_RUN=true
```

Dry Run 允许打开、识别、填写、上传和截图，但禁止点击最终提交按钮。

正式提交必须满足：

- Application 状态为 `READY_TO_APPLY`；
- 所有必填字段通过校验；
- 无未处理的敏感/低置信字段；
- 当前表单快照与用户批准的哈希一致；
- Approval Token 有效且绑定当前 application；
- 未发现已有成功提交事件；
- 未超过每日提交上限。

## 10. 提交结果不确定

如果点击后超时或网络断开：

- 不自动再次点击；
- 先检查成功页、申请列表和已有事件；
- 状态标记为 `SUBMISSION_UNKNOWN` 的运行错误，而不是直接判失败；
- 交给用户确认或通过专用恢复流程核查。

业务主状态枚举可保持不变，`SUBMISSION_UNKNOWN` 作为 BrowserRun/Graph 错误状态记录。

## 11. 截图与审计

至少保存：

- 页面初始状态；
- 填写完成、提交之前；
- 提交之后或错误页面。

截图保存前应尽可能遮挡密码和敏感信息；测试 Fixture 必须完全脱敏。

## 12. 测试

第一阶段为 Adapter 建立本地测试表单或脱敏 HTML Fixture，覆盖：

- 文本、textarea、日期；
- 单选、多选、下拉；
- 文件上传；
- 多步骤页面；
- 必填错误；
- 多个同名元素；
- 登录失效；
- 验证码中断；
- Dry Run 禁止提交；
- 审批快照变化后拒绝提交。

真实网站 E2E 默认只运行到提交前，不在自动测试中产生真实投递。
