# 测试、验收与可观测性

## 1. 总体要求

每个开发任务必须同时交付：

- 实现代码；
- 正常路径测试；
- 至少一个失败或边界测试；
- 必要的文档或迁移更新；
- 可复现的验证命令。

不以“代码能导入”作为完成标准。

## 2. 测试分层

### 2.1 单元测试

覆盖纯函数、规则、Schema 和服务中的小范围逻辑：

- Schema 校验；
- Job fingerprint；
- 状态转换；
- Hard Filter；
- Match score 聚合；
- Evidence 过滤；
- 字段映射置信度；
- 敏感字段判断；
- 审批哈希校验。

### 2.2 集成测试

使用测试数据库和 Fake 外部依赖，覆盖：

- Candidate + Evidence 保存；
- Job upsert 和去重；
- Application + Event 同事务；
- LangGraph 中断与恢复；
- ResumeVersion 与快照元数据；
- Service 到 Repository 的契约。

### 2.3 Prompt/Agent 评测

固定一组脱敏样例，检查：

- Structured output 合法率；
- 事实一致性；
- Evidence ID 覆盖率；
- JD hard/preferred 区分；
- 无证据要求是否进入 gap；
- 字数限制；
- 拒绝代答敏感问题。

单元测试默认使用 Fake LLM，不依赖真实网络和付费 API。真实模型评测单独标记。

### 2.4 浏览器 E2E

优先针对本地测试表单和脱敏 Fixture：

- 字段抽取；
- 填写与上传；
- 多步骤页面；
- 校验错误；
- 登录中断；
- 验证码中断；
- Dry Run；
- 最终审批；
- 提交结果不确定。

真实站点测试默认不得产生正式投递。

## 4. 必测业务不变量

1. `REJECTED` Evidence 永远不能进入最终材料；
2. 无 Evidence ID 的候选人能力描述无法通过事实校验；
3. Hard Filter 不通过时不会被语义分数覆盖；
4. 非法 Application 状态转换被拒绝；
5. 同一 candidate/job 不重复创建有效申请；
6. Dry Run 永远不点击最终提交；
7. 没有有效审批令牌不能提交；
8. 表单哈希变化使原审批失效；
9. 提交结果未知时不会自动重复点击；
10. 日志中不出现配置的 API Key 或 Cookie。

## 5. 每个任务的 Definition of Done

- 满足任务验收标准；
- 新增/修改测试全部通过；
- 原有相关测试通过；
- 无未处理 lint/type 错误（若项目启用）；
- 数据库变更有 Alembic migration；
- 配置变更同步 `.env.example`；
- 用户可见行为变更同步文档；
- 不包含真实密钥、Cookie 或敏感 Fixture；
- 最终汇报列出修改文件和验证命令。

## 6. 建议验证命令

具体命令以项目配置为准，推荐：

```bash
pytest -q
pytest tests/unit -q
pytest tests/integration -q
ruff check .
ruff format --check .
mypy job_agent
```

不要在工具未配置时假装已运行。若项目尚未引入某工具，明确写“未配置”。

## 7. 日志

使用结构化日志，至少包含：

- timestamp；
- level；
- event_name；
- trace_id；
- candidate_id（可哈希）；
- job_id；
- application_id；
- graph/node；
- duration_ms；
- outcome；
- error_code。

禁止记录：密码、API Key、完整 Cookie、身份证号、未脱敏简历全文。

## 8. Trace 与指标

### Workflow

- 运行数、成功率；
- 节点耗时；
- 中断次数；
- 恢复成功率；
- 重试次数。

### LLM

- Prompt 版本；
- Schema 合法率；
- Token 和耗时；
- 修复调用次数；
- 事实校验失败率。

### Browser

- 字段识别覆盖率；
- 自动填写准确率；
- Adapter 失败步骤；
- 登录/验证码中断；
- 提交验证结果。

## 9. Bug 修复流程

1. 用测试或 Fixture 复现；
2. 记录期望与实际行为；
3. 确认属于领域、Graph、Adapter、UI 或外部依赖；
4. 先添加失败测试；
5. 实施最小修复；
6. 运行相关测试和回归；
7. 若契约改变，同步对应设计文档。
