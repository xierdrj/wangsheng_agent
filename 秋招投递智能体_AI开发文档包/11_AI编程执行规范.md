# AI 编程执行规范

## 1. 开始任务前

编程智能体必须：

1. 读取 `00_README_AI开发入口.md`；
2. 读取 `01_产品需求与范围.md`；
3. 读取本文件；
4. 按入口的路由表读取任务相关专题文档；
5. 在 `10_开发路线与任务清单.md` 中定位唯一任务编号；
6. 检查仓库目录、现有代码、测试和 Git 状态；
7. 复述任务目标、范围、验收标准和不做事项；
8. 再开始修改。

## 2. 一次只做一个任务

- 不顺手实现后续里程碑；
- 不在未授权时重构无关模块；
- 不更换已选技术栈；
- 不创建“万能 Agent”绕过既定分层；
- 发现必要前置任务缺失时停止并报告依赖。

## 3. 实施顺序

推荐红—绿—重构：

1. 添加或确认失败测试；
2. 实现满足验收的最小代码；
3. 运行相关测试；
4. 在测试保护下整理代码；
5. 运行回归；
6. 更新文档、迁移和示例配置。

如果是全新骨架任务，先建立可运行的最小测试，再扩展文件。

## 4. 代码规则

- 类型注解覆盖公共接口；
- 使用 Pydantic 作为边界校验；
- 避免裸 `dict` 穿越多个模块；
- 依赖通过构造函数或明确参数注入；
- 外部服务使用 Port/Protocol；
- 时间使用带时区 datetime；
- 文件路径使用 `pathlib.Path`；
- 业务状态使用枚举；
- 不用宽泛 `except Exception` 静默返回 None；
- 不在 import 时连接数据库、调用模型或启动浏览器；
- 不在代码中硬编码密钥和真实个人数据。

## 5. 修改已有项目

- 先读相关文件，不根据文件名猜实现；
- 保留用户已有更改；
- 不删除看似无关文件；
- 不使用破坏性 Git 命令；
- 公共契约变化时搜索所有调用方；
- 数据库变化必须有 migration；
- API/Schema 变化必须更新测试和文档。

## 6. 安全规则

绝对禁止：

- 绕过验证码；
- 未经审批点击最终提交；
- 将 Cookie、密码、Token 写入日志或仓库；
- 为候选人生成无证据事实；
- 自动回答法律声明、背景调查和重大个人选择；
- 在测试中向真实招聘网站提交申请。

涉及浏览器提交的任何实现默认 `dry_run=True`。

## 7. 工具和外部信息

- 对依赖 API 不确定时查官方文档；
- 不根据记忆猜测最新 LangGraph/Playwright 接口；
- 优先使用项目锁定版本对应的文档；
- 引入新依赖前说明原因、替代方案和影响；
- 不为简单问题增加大型框架。

## 8. 测试与验证

完成前必须运行最相关的测试。若不能运行：

- 明确说明原因；
- 不宣称通过；
- 给出用户可执行的命令；
- 区分代码问题与环境问题。

## 9. 文档更新

当实现与设计发生合理差异时：

1. 不静默偏离；
2. 说明为什么；
3. 更新对应专题文档或创建 ADR；
4. 确保入口索引仍正确。

任务状态应在用户确认或实际验收后改为 `DONE`。编程智能体可以报告“实现完成，待验收”，不要虚假标记。

## 10. 最终汇报格式

```markdown
## 结果
一句话说明完成了什么。

## 修改文件
- path：用途

## 关键实现
- 设计决策和重要边界

## 验证
- `命令`：结果

## 未完成或风险
- 没有则写“无”

## 下一步
- 建议的唯一后续任务编号
```

## 11. 遇到歧义时

以下情况停止并提问：

- 首个目标 ATS 未指定且任务依赖平台细节；
- LLM Provider、模型或调用方式会改变架构；
- 现有代码与文档在核心契约上冲突；
- 操作会真实提交、发送消息、删除数据或覆盖重要文件；
- 缺少候选人的事实信息而生成任务要求最终材料；
- 网站条款或权限明显不允许自动化。

普通命名和局部实现细节可按现有约定自行决定，不应为低影响选择频繁阻塞。
