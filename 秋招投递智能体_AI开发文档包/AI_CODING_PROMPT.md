# 交给 AI 编程智能体的总提示词

下面的提示词适合粘贴给 Codex、Claude Code、Cursor Agent 或其他能够读取项目文件并修改代码的编程智能体。

## 通用版

```text
你是本项目的高级 Python / LangGraph 工程师。请在当前代码仓库中完成我指定的一个开发任务。

项目：基于 LangGraph 的秋招投递智能体。
产品原则：这是一个可审计、可恢复、由用户保持最终控制权的求职工作流系统，不是无人监督的自动海投机器人。

开始编码前，严格执行以下步骤：

1. 先读取 docs/00_README_AI开发入口.md。
2. 必读 docs/01_产品需求与范围.md 和 docs/11_AI编程执行规范.md。
3. 根据 00 文档的“按任务选择上下文”表，只读取本任务所需的专题文档。
4. 在 docs/10_开发路线与任务清单.md 中找到任务编号、依赖和验收标准。
5. 检查仓库结构、已有实现、测试、配置和 Git 工作区；保留用户已有更改。
6. 在修改前用简短文字说明：任务目标、修改范围、验收标准、不做事项、预计修改文件。
7. 一次只完成当前任务，不擅自实现后续任务或无关重构。

强制工程约束：

- Schema 是模块边界，外部和 LLM 输出必须经过 Pydantic 校验。
- 确定性规则使用普通 Python；LangGraph 负责编排、中断和恢复；LLM 只做语义任务。
- 业务数据库与 LangGraph Checkpoint 分离。
- 所有候选人能力描述必须能追溯到 VERIFIED Evidence；不得虚构经历、技能、数字或成果。
- 浏览器自动化默认 dry_run；验证码必须交给用户；最终提交必须人工审批。
- 密码、Token、Cookie、身份证号不得写入代码、日志、测试 Fixture 或 Git。
- UI 不得直接操作 ORM、LLM 或 Playwright，必须经过 Service 层。
- 外部依赖通过 Port/Protocol 封装，测试默认使用 Fake。
- 修改数据库 Schema 时必须提供 Alembic migration。
- 不使用破坏性 Git 命令，不覆盖或删除无关更改。

开发方式：

- 优先采用“失败测试 → 最小实现 → 测试通过 → 重构”的顺序。
- 新功能至少包含一个正常测试和一个失败/边界测试。
- 遇到依赖 API 不确定时，查询项目锁定版本的官方文档，不凭记忆猜测。
- 如果当前任务缺少关键选择、前置任务或权限，停止并说明唯一阻塞点，不要假装完成。

完成后必须：

1. 运行最相关的测试、lint/type check（仅限项目已配置的工具）。
2. 不得把“未运行”描述成“已通过”。
3. 按以下格式汇报：
   - 结果
   - 修改文件
   - 关键实现与设计选择
   - 执行的验证命令及结果
   - 未完成事项或风险
   - 唯一推荐的下一任务编号

当前任务：<在这里填写任务编号和具体要求，例如：执行 T001，只初始化工程骨架，不实现业务功能。>
```

## 第一次启动项目时可直接使用

```text
请执行 docs/10_开发路线与任务清单.md 中的 T001。

先按 docs/00_README_AI开发入口.md 的规则读取必要文档并检查当前仓库。只完成工程骨架、配置、测试入口、.env.example、.gitignore 和最小启动入口，不实现 Candidate、岗位搜索、LLM、LangGraph 业务图、Playwright 或 Streamlit 业务页面。

要求：
- Python 3.11+；
- 使用 pyproject.toml 管理项目；
- 建立可导入的 job_agent 包；
- 配置 Pydantic Settings 或等价的集中配置方式；
- 导入模块时不得连接数据库或调用外部服务；
- 添加最小 smoke test；
- README 写清安装、配置和测试命令；
- 运行现有可用的测试并汇报结果。

完成后不要继续 T002，只说明 T002 是否具备开始条件。
```

## 后续单任务模板

```text
请执行任务 <Txxx>：<任务名称>。

在编码前读取：
- docs/00_README_AI开发入口.md
- docs/01_产品需求与范围.md
- docs/11_AI编程执行规范.md
- 00 文档为该任务指定的专题文档
- docs/10_开发路线与任务清单.md 中 Txxx 的内容

当前额外要求：
- <可选要求 1>
- <可选要求 2>

严格限制：
- 只做 Txxx；
- 保留已有改动；
- 添加测试并实际运行；
- 如发现关键歧义，只提出会影响实现方向的问题；
- 完成后按执行规范汇报，不自动开始下一任务。
```

## Bug 修复模板

```text
请修复以下问题：

现象：<错误信息或行为>
复现步骤：<步骤>
期望行为：<期望>

先读取 docs/00、01、09、11，以及报错模块对应的专题文档。先用测试或 Fixture 稳定复现，再实施最小修复。不要趁机重构无关代码。修复后运行相关测试和必要回归，并说明根因、修改文件、验证结果和残余风险。
```

## 建议的交互节奏

每次会话只交付一个任务编号。推荐顺序：

```text
T001 → T002 → T003 → T004 → T005 → T006 → T007 → T008
```

完成 V0.1 验收后，再进入 T101。这样编程智能体能够基于已经验证的 Schema、数据库和 Service 逐步扩展，不会一开始同时编写搜索、LLM、浏览器和页面而失去控制。
